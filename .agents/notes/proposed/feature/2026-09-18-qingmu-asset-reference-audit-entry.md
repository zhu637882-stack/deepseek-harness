# Agent Note: Qingmu asset reference audit cockpit entry

Status: proposed

English | [中文](2026-09-18-qingmu-asset-reference-audit-entry.zh.md)

## Problem

The Writer already owns a complete per-asset image audit. In the writer repository (`workflow-pilot-20260909/writer`), `ConsistencyService.run` (`backend/src/jason/apps/studio/consistency_service.py:4826`) submits one `vision.audit` call per asset with `route_key="b4_5.consistency"`, `audit_layer="asset"` and `audit_mode="frame"` (line 4910), scores it against `_rubric_for_asset` (line 1371), writes the verdict back with `merge_asset_production_quality(quality_status="passed" if passed else "failed")` (line 5001), and produces `_repair_prompt_for_asset` (line 1723) for the failures. `POST /api/projects/{project_id}/episodes/{episode_id}/asset-references/audit/preflight` (`backend/src/jason/apps/studio/api.py:9671`) prices a batch with `dry_run=True`, and `POST .../audit/start` (`api.py:9718`) consumes that quote through `task_center.consume_asset_reference_audit_preflight_and_create_parent` (`backend/src/jason/domain/task_center.py:11943`), which requires exact equality of `requested_by_user_id`, `project_id`, `episode_id`, `source_lock_hash`, `call_plan_hash` and `confirmation_text`, plus `allowed = 1` and an unexpired row. `asset_reference_batch_worker.py:18` executes the queued parent and admits only `actor:{identity_board, turnaround_front}`, `scene:{scene_reference}`, `prop:{prop_reference}`.

Nothing in the harness reaches any of it. Both harness checkouts contain zero references to `asset-references`, so there is no bridge and no cockpit surface. The audit has therefore never run, which four independent read-only queries against the live runtime database confirm: `provider_preflights` holds 78 rows with `capability = 'vision.audit'` and every one of them is `qingmu.candidate_review.native_video` (74) or `qingmu.working_cut.sound_review` (4), with no `b4_5.consistency` row, no `workflow.asset_reference_batch` row and `consumed_by_task_id` null on all 78; `generation_tasks` has zero rows with `route_key LIKE 'b4_5%'` and zero with `capability = 'workflow.asset_reference_batch'`; `consistency_checks` is empty; and all 204 materialized image assets (72 `prop_reference`, 54 `scene_reference`, 37 `turnaround_front`, each with a stored sha256 and a local file) still carry `quality_status = 'pending'`.

The consequence reaches past the asset stage. Because no asset ever received a machine verdict, `quality_status` never moved off `pending`, so no failure reason was ever available to feed `shot_issue_rules`, and the capsule learning loop stayed starved at its input. This is the same defect class as the storyboard human review gate: the Writer side is finished and the harness has no entry point.

## Proposal

Add the missing entry point as one command bridge and one cockpit panel, following the `entity-draft-review` and storyboard review templates already proven in this repository. No read bridge is needed: the quote response is the state.

**A command bridge** — [asset-reference-audit.ts](../../../../packages/experimental/qingmu-yimeng-command-adapter/src/asset-reference-audit.ts) registers the exact Host routes `/api/qingmu/asset-reference-audit/quote` and `/api/qingmu/asset-reference-audit/start`. Both forward only the caller's own `jason_token=` cookie (bounded at 8192 bytes, refused if it contains CR or LF), refuse any request carrying `authorization`, require `isTrustedApiRequest`, and require `origin === http://${host}` with the forwarded `origin` and `host` rewritten to the upstream, matching `require_human_browser_cookie_write` on the Writer side. The query must carry exactly `projectId` and `episodeId`; the quote body must carry exactly `auditMode` and `assetIds`; the start body must carry those two plus `preflightId`, `sourceLockHash`, `callPlanHash`, `confirmationText` and a literal `confirmed: true`. Requests are capped at 64 KiB and responses at 256 KiB, and a `content-length` that understates the body is refused.

The bridge holds no cost policy of its own — `allowed` and `quoteAllowed` stay the Writer's decision — but it refuses to relay a quote that contradicts the free-quote promise: `providerCalls` must be `0`, `budgetMutation` and `taskMutation` must be `false`, `readOnly` must be `true`, `imageRegeneration` must be `false`, `callCount` must equal `manifest.length`, and `authorizationCapCny` must be present and not below `estimatedCny`. Every manifest item must carry exactly the 19 keys the Writer emits, and `capability`, `routeKey`, `imageRegeneration` and `auditMode` are checked rather than passed through, so a manifest item claiming `image.generate`, a first-frame route key, or image regeneration is reported as 502 instead of reaching the browser as a price the operator might authorize. A start receipt is accepted only when `accepted === true` and `task.capability === 'workflow.asset_reference_batch'`.

Outcome classification follows the storyboard bridge. A 5xx, a transport failure, and any 2xx whose receipt cannot be validated all become 502, because both routes mutate Writer state before responding — the quote writes a preflight row and the start consumes it and queues a paid batch — so the action may already have landed and the caller must re-read rather than resubmit. Only a definitive sub-400 Writer rejection becomes 409, carrying the Writer's own reason code from its FastAPI `detail` when it reports one. An upstream 401 or 403 becomes 401 so the panel returns the operator to login.

The guard itself is no longer per-bridge. [human-browser-bridge.ts](../../../../packages/experimental/qingmu-yimeng-command-adapter/src/human-browser-bridge.ts) now holds the one copy of `browserWriteHeaders`, `readJsonBody`, `jsonResponse`, `writerCode` and `isRecord`, and both this bridge and the storyboard review bridge import it. The storyboard bridge carried a byte-identical copy of all five until this change; a third copy would have meant three places to edit if the cookie bound, the origin rule or the relayed-code pattern ever needed fixing. Each bridge keeps its own byte bound and passes it to `readJsonBody`, because the two bounds are derived from different Writer field limits. `entity-draft-review.ts` keeps its own guard, which genuinely differs: it serves reads as well as writes, so it enforces the origin check only on writes and omits the JSON content type on GETs.

**A cockpit panel** — [AssetReferenceAudit.tsx](../../../../packages/experimental/client-ui-qingmu-cockpit/src/client/AssetReferenceAudit.tsx), rendered from [QingmuCockpit.tsx](../../../../packages/experimental/client-ui-qingmu-cockpit/src/client/QingmuCockpit.tsx) inside the asset view only once an episode is bound, and keyed by project, episode and audit mode so switching scope discards the previous quote. It requests nothing on mount: quoting is one button press, and the audit mode is chosen explicitly between `new_candidates` and `rule_reaudit`, with a mode change dropping any quote already on screen. The quote renders its estimated and capped CNY amounts, its call count, its expiry, the Writer's per-image `validationErrors` verbatim, and one manifest line per image naming its role, label, price, whether the gate allows it, and whether it has ever been audited.

The start control renders only when `quoteReady` is true and the manifest is non-empty, and stays disabled until the operator ticks a checkbox saying they read every manifest line. It sends the Writer's own `confirmationText` back verbatim along with the four fields the Writer binds the preflight to, so a quote that changed underneath is refused by the Writer rather than silently re-priced. On a 502 the panel drops both the tick and the quote, so a batch whose outcome is unknown can never be resubmitted by the same click; the operator must re-quote deliberately. Spending money is the operator's click alone and nothing here quotes or starts on a timer, on mount, or on another route's success.

The bridge registers through `ctx.effect(...)` in the package [index.ts](../../../../packages/experimental/qingmu-yimeng-command-adapter/src/index.ts) and returns both `webServer.register` disposers, so teardown unregisters the exact routes.

## Scope and blast radius

Harness only. No Writer change, no schema change, no migration. No live build, deploy, or runtime-root write: the code stops on branch `qingmu-self-learning-loop-20260916` for review. Neither route was invoked against the live stack while writing this, because the free quote still writes a `provider_preflights` row and the start spends money; both remain the operator's action. The panel calls no provider itself and the bridge verifies the Writer's free-quote promise against the receipt instead of assuming it. Login reuses the existing `/api/qingmu/editorial-handoff/human-session` route rather than adding a second credential path.

## Alternatives considered

**Let the director agent request the audit.** Rejected. The batch is paid, and an agent that can queue paid `vision.audit` calls removes the operator from the spending decision. The agent may read the resulting `quality_status`; only the operator may buy it.

**Auto-quote on mount so the panel always shows a price.** Rejected. The quote is free of provider calls but it is not free of writes: each one inserts a preflight row with a 30-minute expiry. A panel that quotes on every episode switch fills that table without an operator asking for anything.

**Put a spend cap in the bridge.** Rejected. `provider_gate.preflight` already computes `allowed` and `quoteAllowed` from the project's authorization. A second cap in the harness would be a tunable duplicated across repositories, and the two would eventually disagree. The bridge relays the Writer's decision and refuses only quotes that contradict their own stated invariants.

**Accept the Writer's per-asset ids from the browser.** Kept but constrained: the bridge forwards `assetIds` and validates each against `^[A-Za-z0-9][A-Za-z0-9._:-]{0,255}$` with duplicates refused and a 100-item ceiling matching the Writer's own `max_length`. The panel always sends an empty list, so the whole episode is quoted, and a narrower selection stays available to a future surface without a bridge change.

## Risks

**The browser → Host → Writer chain is not verified end to end.** An e2e in the shape of [qingmu-entity-draft-human-review.e2e.ts](../../../../apps/web/tests/qingmu-entity-draft-human-review.e2e.ts) is the right next step and is deliberately not included: it needs a qingmu-profile client build, Playwright Chromium and the Writer fixture venv, and the host disk had 9.1 GiB free at the time of writing, below the 10 GiB threshold this project stops heavy work at. The field names the bridge validates were instead confirmed by reading the live Writer source, including the manifest key set at `api.py:9575` and the four bound fields at `api.py:9745`. Source agreement is not an executed transcript, so treat the wiring as reviewed, not proven.

**Older assets may all be unquotable.** The quote resolves each image through `_public_media_url`, and `_require_real_url` on the audit path accepts only an HTTPS URL or a base64 image data URL of at most 20 MB, while generated asset links expire after 24 hours. Assets whose link has expired and whose file is too large to inline would all land in `validationErrors` as `public_provider_media_url_missing`, producing a blocked quote with an empty manifest. That fails closed and spends nothing, but it would present as an audit that cannot be started. Confirming it needs one real quote against live, which is the operator's action.

**A Writer 422 is reported as 409.** Pydantic rejection of the bridge's own upstream body would surface as a definitive rejection rather than as a bridge defect. It fails closed and cannot queue a duplicate batch, but it would misdirect diagnosis.

**A start whose receipt is unreadable leaves a queued batch behind.** The 502 tells the operator the outcome is unknown and refuses to resubmit, but the harness has no route that reads back `generation_tasks`, so confirming whether the batch landed means querying the runtime database directly. A read bridge for batch status is the natural follow-up and is not included here.

**The three human-review panels still each carry their own login form.** `EntityDraftHumanReview.tsx`, `StoryboardHumanReview.tsx` and the new `AssetReferenceAudit.tsx` duplicate the same credential inputs and the same login helper, which clone detection reports as four pairs. Extracting one shared sign-in block would touch two panels that are already committed and reviewed, so this change stopped at the bridge-level guard, where the duplicated code decides who may spend money. The panel-level extraction is a separate simplification.
