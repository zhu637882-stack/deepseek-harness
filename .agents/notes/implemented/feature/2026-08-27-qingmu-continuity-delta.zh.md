# Agent Note：青木只读连续性证据

Status: implemented

[English](2026-08-27-qingmu-continuity-delta.md) | 中文

## 问题

历史连续性检查可能已通过，但选中视频、尾帧或下一镜头首帧已变化。把该检查显示为当前镜头链的批准，会抹去来源边界。缺失维度也不能变成失败或正式 Finding。

## 决策

易梦拥有可选的 `director.continuityDelta` 工作流投影。只读适配器校验其规范相邻镜头顺序、来源修订、快照哈希、当前资产绑定、原始审计声明及派生就绪状态。审计 SHA 缺少其原始资产 ID 时仍保留为历史证据，但不能证明就绪。

`continuityMethod` 只接受项目、剧集及所选镜头三个 ID。Host 重新读取已配置的 `qingmuYimengRead` 能力，再把有界快照交给无状态 Core 编译器。Host 复核精确输入与来源哈希、十四份本地规则文件哈希、前后相邻镜头、失败候选及不执行边界。不新增上游配置、项目数据库或 HMAC 授权。

既有共享镜头选择驱动连续性面板。面板分开当前绑定、历史检查、缺失证据及四个已记录维度。只有明确为 false 的维度产生候选；严重度、最早责任岗位及时间码保持 null，等待归因。六种锁定义和五条返修规则是方法模板，不是项目锁实例或可执行任务。刷新、来源错误、关闭和镜头切换均使旧响应失效。

## 考虑过的替代方案

**把最近一次通过的检查当作当前批准。** 审计必须匹配实际选中资产和选中视频血缘。保留历史通过记录，但不据此授予当前就绪状态。

**从方法规则推断正式 Finding 或锁实例。** 既有来源不提供这些权威。响应明确报告锁实例不可用及候选待归因。

**接受浏览器提供的快照。** 浏览器仅提供三个 ID。Host 侧实时重读和规则原始哈希把方法绑定到当前来源。

## 影响

面板提供可追溯的连续性证据，不创建第二套 DAG、不自动返修资产、不写业务状态、不调用 Provider，也不批准内容。单元测试覆盖绑定和权威失败；Chromium 通过真实 Host 和 Core，针对 loopback 易梦测试替身验证当前、历史、不通过、未知及缺失证据。新增浏览器用例恢复入口页签，使原有严格请求次数测试保持隔离。
