# Agent Note: 青木离线 Gate A 控制证据

Status: implemented

[English](2026-08-28-qingmu-gate-a-control-evidence.md) | 中文

## 问题

E6-3 必须在允许任何真实 Provider 或正式数据库之前，证明提交至多一次、`submission_unknown` 隔离、对账以及轮询／下载恢复。证明还必须绑定产生它的准确易梦实现。Harness 需要让小型制作团队能够使用这些证据，同时不能变成第二套故障注入执行器、任务对账器、工作流或权威来源。

## 决策

易梦拥有唯一一份内容寻址的 `jason.qingmu-provider-gate-a-control-evidence.v1` 回执。它由离线执行器在临时 SQLite、脚本化 Fake Provider 和禁止网络外连的环境中生成。回执记录八个准确场景：未授权拦截、重复确认回放、载荷 SHA 冲突、未知提交隔离、模拟对账、轮询恢复、下载超时恢复和截断下载拒绝；同时绑定实现这些控制的源码文件及其 SHA-256。

青木只读适配器新增一个受保护且无请求体的 GET 投影。它只接受空 RPC 载荷，并独立校验准确 schema、场景顺序、逐场景断言、源码路径顺序、源码哈希、运行环境、零权限计数和 RFC 8785 JCS 证据 SHA。任何字段或权力漂移都会在数据到达浏览器前失败关闭。

“生成与质检”延迟把已校验回执渲染为只读卡片。界面分开显示离线通过状态与尚未验证的真实付费生产，展示全部场景、必须为零的计数，以及可核查的源码／证据哈希。唯一控件用于重读回执；不能运行故障注入、提交、对账、预留、生成、批准或推断签收。

## 考虑过的替代方案

**直接渲染易梦 JSON。** 这会缺少独立 Host 边界，也可能让过期或带权力的字段进入浏览器。适配器改为校验完整准确合同。

**从浏览器运行故障注入。** 这会复制一套安全关键执行器，并在用户界面暴露执行控制。浏览器只读取已经生成且绑定源码的回执。

**在证据旁暴露提交或对账动作。** 这会让离线 Gate A 证明看起来像生产授权。本切片不存在这些命令。

## 影响

团队可以看到有边界的离线控制套件已经通过，包括重复付费提交为零、未知状态自动重提为零；界面同时持续说明真实付费生产尚未验证。源码漂移会使回执失效，而不是悄悄保留通过结论。

适配器测试覆盖有效回执、准确受保护 GET、空载荷规则，以及重新计算证据 SHA 后仍带权力漂移的对抗输入。客户端测试覆盖全部场景与零值、重读、失败和延迟响应取消。真实 Loader/Connection 与 Chromium 验证出厂青木组合只发送一次带认证 GET 和空 RPC 载荷，界面只暴露重读控件，没有上游 POST，并在桌面与移动尺寸可用。全部测试使用隔离回环替身，不调用真实 Provider。

这些检查不创建或授权付费 Provider 调用、正式预留、正式数据库或预算账本写入、任务、队列、提交、真实对账、部署、发布、人工签收、ProviderGate 变更、模型路由变更、push 或生产通过结论。

## 验证边界

这只关闭有边界离线环境中的 E6-3 Gate A 控制逻辑证据。`PASSED_CONTROL_LOGIC_ONLY` 不会变成生产通过。真实付费生产仍为 `UNVERIFIED_FOR_PAID_PRODUCTION`，直到后续方案门禁取得独立的准确授权与证据。
