# Agent Note: 青木已选 Take 验收证据

Status: implemented

[English](2026-08-28-qingmu-take-acceptance-evidence.md) | 中文

## 问题

Take 已被选择且本地文件可解码，并不能证明 Provider 提交真实、创意检查仍是当前版本，也不能证明正式生产验收已经发生。如果把其中一项当成其他几项，Harness 就会形成第二套批准权威，还可能把 dry-run 或过期证据错误提升。

## 决策

易梦拥有当前已选 Take 的唯一只读验收证据对象。Harness 只接受项目、剧集与帧坐标，在编译前后读取该对象，验证其 RFC 8785 摘要，并且不转发路径、URL 或 Provider 原始响应。IMAGO 只根据这份精确证据和七份固定当前规则文件编译无状态方法。

方法严格分开三层证据：整片严格解码与按帧数推导的实际平均帧率、来自易梦当前检查的宏观和微观 QC、Provider outbox 回执。标称帧率不等于实际帧率。对白音频 QC 只在易梦声明的当前必检集合中按条件要求。未激活的参考叠加文档提供经评审的 QC 维度，但仍保持未激活。

Harness 独立重建方法定义、评估、来源哈希和规则摘要。编译后再次读取证据与规则，发生漂移就失败关闭。Host 专用 HMAC 绑定已校验投影。响应始终明确：付费生产未验证、Selected 不等于 Approval、Gate B 未完成、正式验收不可用。

## 考虑过的替代方案

**根据已选素材或严格解码推断验收。** 这些事实只证明身份与本地可读性，不能证明真实 Provider 回执、当前创意 QC 或人工批准。

**把 Provider 与 QC 事实复制进 Harness 数据库。** 这会产生第二业务真源和同步问题。每次重新读取易梦可以保持现有权威边界。

**为了使用 QC 维度而激活参考叠加策略。** 当前策略明确处于未激活状态。方法只验证其中经评审的维度，不改变激活或路由状态。

**在证据视图中同时提供 Gate B 或批准命令。** 本切片没有认证人工决定或 Provider 特定完成合同。方法保持只读且不批准。

## 后果

同一个对比界面可以分别展示本地解码、宏观 QC、微观 QC 与 Provider 证据是否满足，而不夸大生产就绪状态。证据或规则漂移、伪造编译器字段、能力缺失、取消和签名密钥缺失都会失败关闭。额外读取和子进程带来有界本地延迟。正式 Gate B、人工签收、付费提交、写入和参考叠加激活仍不属于本方法。
