# Agent Note: 青木 Take 普通评论

Status: implemented

[English](2026-08-28-qingmu-take-comments.md) | 中文

## 问题

小型制作团队需要在精确 Take 的精确位置讨论内容，同时不能把评论变成 Finding、质量决定、选择或批准。只把评论挂在当前可见行上，会在 Take 版本或当前选择变化后发生漂移；把评论复制到 Harness 又会形成第二业务真源。

## 决策

普通评论账本由易梦独占。每条评论不可变，并绑定精确的 Take 主体 SHA、Take ID、输出 SHA、镜头血缘，以及时间码或帧锚点。只读适配器只接受项目、剧集与镜头坐标，执行一次认证 GET，校验当前版本主体及其 SHA 身份的准确性，并同时暴露当前与历史绑定。

命令适配器接收一份完整浏览器意图，但单次 POST 正文只发送五个字段：预期 Take 主体 SHA、Take ID、锚点、正文和幂等键。路径 ID 来自 URL，actor、评论者角色与 session 只来自易梦认证。结果必须把选择、技术通过、正式批准、单集验证、人工签收、Provider 调用与预算影响保持为零或 false。

POST 前，浏览器把完整、非秘密的意图存入 `sessionStorage` 并立即读回核对。结果不确定时，只使用原主体 SHA、Take ID 与幂等键执行 GET 回执查询；POST 绝不重试。存在 Selected Take 时，表单初始跟随该版本，但在评论面板内选择其他版本绝不会改变选择。

## 考虑过的替代方案

**所有评论都复用 Finding。** Finding 带有审核严重度、责任归属与返修语义，普通协作不应暗示这些含义。

**只把评论绑定到当前选中行。** 选择会变化，这会让记录失去赋予评论意义的准确媒体和版本血缘。

**结果不确定后重试 POST。** 即使有幂等机制，自动重提也会掩盖“写入未知”与“回执已确认”的区别。只读 GET 恢复可以保留这项区别。

**在 Harness 保存镜像评论账本。** 第二账本会分裂权威并引入对账问题。因此 Harness 只校验和展示易梦账本，不持久化业务真源。

## 后果

团队成员可以在任一当前 Take 上留下精确的时间码或帧锚定评论，版本变化后仍可阅读历史评论。当前绑定由系统推导并校验，而不是由浏览器猜测。严格 schema、Host 专属凭据、精确结果核验与只读 GET 恢复会在漂移或凭据反射时失败关闭。本功能明确不创建 Finding、播放、技术通过、批准、单集验证、人工签收、Provider 动作、预算变更或 Take 选择。
