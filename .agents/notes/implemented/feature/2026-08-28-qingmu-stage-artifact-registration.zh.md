# Agent Note：青木机器校验阶段工件登记

状态：已实现

[English](2026-08-28-qingmu-stage-artifact-registration.md) | 中文

## 问题

当前 IMAGO V6 阶段工件已有通过校验的 Core 与后端合同，但还没有接入 Harness 既有 Host 路由。若不重新运行当前编译器并绑定准确工件字节就直接转发，过期规则或浏览器提供的权威声明可能越过边界。对结果不确定的登记自动重试，还可能造成第二次业务写入。

## 决策

既有 IMAGO 方法适配器增加 `stageArtifactMethod`。它只接受业务坐标与一份完整 V6 阶段工件，规范化不超过 1 MiB 的输入，派生独立主体 SHA，并调用真实的当前 Core 编译器。它只限阶段工件的规范 JSON 对所有获准有限数字都是 Core Python 加载/转储路径的定点表示，包括小数、指数边界和负零；非有限数字失败关闭。Host 在编译前后独立读取并哈希十一份固定 Core 来源，重建所选阶段定义，拒绝规则漂移或伪造编译输出，并只用现有 Host 专属 HMAC 密钥签署已验证的登记投影。

既有易梦命令适配器增加 `registerStageArtifact` 与 `recoverStageArtifactRegistration`。登记在单次 POST 前核验工件、主体、当前阶段定义及其版本、机器校验结果、规则哈希、投影 SHA 和 HMAC，并携带明确的记录 CAS 条件；发出的工件使用同一组阶段规范字节，而且在传输前必须符合易梦按字符串识别的 64 层物理 JSON 嵌套上限。actor、自然人身份与 session 仍是易梦认证事实。回执必须保留准确工件和认证生产者，同时工件可用性、依赖、批准、锁、计划、签收、返修和 Provider 权威标记全部保持 false 或零。成功的阶段响应会保持完整直到整份回执校验结束，合法的 `token` 业务字段不会丢失；校验后的任意键或字符串若包含实际 bearer 凭据则失败关闭。非成功正文和校验失败仍会被脱敏或替换为静态错误。

结果不确定的 POST 绝不重试。恢复只使用原始项目、单集、阶段、范围、主体 SHA 与幂等键发送无正文 GET；即使今天的工件、HMAC 密钥或历史会话已经变化，也会重新校验原始持久回执。Harness 不增加数据库或第二套业务状态机。

## 考虑过的替代方案

**把工件直接转发给易梦。** 这会遗漏既定编译器边界要求的当前 Core 校验和独立规则字节检查。

**把机器校验当成依赖核验或批准。** 登记只证明准确工件通过确定性阶段校验。依赖权威与独立审核仍是后续明确检查点。

**响应丢失后重新提交。** 只有原回执查询能在不追加写入的情况下确认第一条命令的结果。

## 影响

聚焦测试覆盖准确请求与回执 schema、小数、指数阈值及负零之间一致的规范工件身份、1 MiB 上限、当前规则哈希、定义版本漂移、伪造编译输出、HMAC 绑定、记录 CAS、生产者与会话绑定、业务 `token` 保留、实际凭据反射拒绝、无权威标记、畸形回执、取消和秘密脱敏。真实 Cordis Loader/Connection/WebServer 组合会调用当前 Core 编译器与隔离易梦 HTTP 双替身；测试故意丢失 POST 响应、关闭 Method 插件、轮换 HMAC 密钥和 bearer 会话、用一次 GET 恢复原回执、重新启用插件，并证明没有第二次 POST。同一组合还证明：真实 Core 可以接受的一份 70 层阶段载荷，会因为序列化命令超过易梦路由嵌套上限而在 fetch 前被拒绝。

本检查点不增加 UI、依赖权威决定、独立阶段批准、锁激活、LSU 计划封存、返修执行、Provider 调用、正式数据库修改、部署或 push。
