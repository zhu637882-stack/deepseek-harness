# Agent Note：青木已保存剧本来源引用

状态：已实现

[English](2026-08-28-qingmu-stage-source-bindings.md) | 中文

## 问题

易梦已保存剧本是业务工件，不等于通过审核的 IMAGO 剧本包。读取方法、编辑未保存草稿或恢复旧回执，都不得悄悄制造当前来源登记或阶段权威。

## 决策

三个既有 Host 插件扩展来源读取、当前方法准备、显式登记和原回执恢复。来源描述绑定项目、单集、已保存修订与完整剧本内容哈希，包含编辑元数据；描述自身的哈希与内容哈希分开。方法适配器只接受坐标，重读来源、调用当前 Core、验证固定九份规则与仅来源定义，并在签发 Host 证明前再次核对来源和规则。

既有剧本工作区在已保存剧本旁显示来源引用。登记必须具有所有者能力、匹配已保存坐标，并获得明确确认；编辑器草稿不进入登记。单次 POST 前，客户端写入并回读十字段、无秘密的恢复标记。原签名投影连同来源及绑定修订/SHA 比较条件原样传递。三账本原子事务归易梦；Harness 不增设数据库或业务状态机。

POST 结果不确定时绝不重试。即使当前来源或方法不可用，也只能显式 GET 查询原坐标回执。回执验证后，仅条件清除匹配的原标记，再触发权威回读；旧回执本身不能渲染当前登记。当前来源是否一致与当前方法规则是否一致分开判断。关闭、范围或端口切换、来源变化、取消与迟到响应均使旧工作失效。

仅此新操作的幂等键限制为 8–200 个 U+0021–U+007E 可见 ASCII 字符。POST JSON 与恢复 HTTP 头携带完全相同的值，两端均不裁剪或编码替换。此限制不改变项目或单集的 Unicode 标识，也不影响其他命令。真实复现证明：原先某些键能被 POST 接受，却在 GET 恢复时被 Fetch 拒绝；本规则修复该断链。

## 考虑过的替代方案

**借用剧本编辑制造无变化提交。** 来源引用是独立的显式意图，不得改剧本内容，也不能把原生剧本 ChangeSet 引用当成已可信绑定的方法。

**把登记当作剧本包或审核。** 方法描述专业要求，但来源登记不生产工件、不创建 Stage 实例、不激活锁、不封存计划，也不使工作单可执行。

**响应不确定时重新提交。** 只有原回执查询能在不追加写入的前提下确认原命令结果。

## 影响

Host 与客户端聚焦测试覆盖精确合同、来源与规则漂移、Unicode 业务标识、安全整数修订、过期比较条件、权限、存储失败、恢复标记替换、取消、畸形回执，以及不依赖当前方法密钥的恢复。真实 Loader/Connection 测试调用当前 Core，并使用隔离 HTTP 上游。原生 Fetch 测试证明非法键在发送前被拒绝，合法键在 POST 到 GET 之间不被改写。

真实 Chromium 验证编辑器保有未保存草稿时显式登记已保存版本、丢失 POST 响应、刷新页面、来源不可用时查询原 GET 回执与权威回读。仅来源的历史面板有装配后的无障碍快照，并检查既有工作区的桌面与移动端。浏览器上游是本地 HTTP 测试替身；易梦事务另由临时 SQLite 和隔离 API 测试证明。这些测试不是实际账号登录切换测试，也不代表正式部署。

本检查点不包含 Provider 调用、Worker、自动返修、剧本审核、人工内容签收、正式数据库修改、部署或 push。
