# Agent Note: 将创作技能保持为休眠的带版本目录

状态：已实现

[English](2026-09-02-qingmu-creative-skill-catalog.md) | 中文

## 问题

青木 OS 已有准入的导演方法资产和易梦风格包库，但缺少一个可供创作设置消费、面向产品的可读技能约定。直接暴露仓库名称或文件会把来源组织泄漏到产品中；复制或激活这些来源则会产生第二套工作流、许可证歧义和权威升级。

## 决策

实验性 `qingmu-creative-skill-catalog` 包把 `qingmu.creative-skill-catalog.v1` 构建为纯数据。每张卡使用中文、带版本、支持范围、默认关闭，并绑定方法、内容、来源、谱系和许可证哈希。六个基础类别通过现有注册表和包校验器复用准确准入的 IMAGO 内容。仓库身份只保留为追踪谱系。

易梦风格包只能作为现有认证读取边界的可选准确字节投影进入。调用方只提供字节；来源身份、schema、来源修订、规范快照 SHA、源内容 SHA、内部许可证引用和只读使用边界均由包内账本固定。它产生可读视觉卡，但不复制提示词片段。未知来源、许可证不匹配、重复 ID、无效范围、关系错误或 SHA 漂移均失败关闭。

目录构建不执行注册、激活、写入、Provider 调用、预算变更或批准。未来的创作设置消费方可以展示和筛选结果，但明确选择仍属于该消费方的现有权威。

## 考虑过的替代方案

**暴露已准入的仓库和 skill 文件名。** 拒绝，因为来源组织不是稳定的产品词汇，也没有向创作者描述可复用方法。

**复制易梦库或增加另一条 Harness 读取链。** 拒绝，因为这会复制来源权威，并携带未经核验的许可证和新鲜度边界。

**把每张卡登记成可执行 skill。** 拒绝，因为目录可见性不等于执行、Provider、批准或工作流权威。

## 验证

聚焦测试覆盖确定输出、全部六类、调用方伪造的易梦字节、未知来源、未准入许可证、重复 ID、无效范围、关系错误、来源字节漂移、可信内容绑定和不可变输出。实时只读 smoke 覆盖包内固定的易梦投影。包类型检查、lint、构建、工作区约定和文档同步仍是集成门禁。

## 后果

创作设置现在具有一个确定的集成接口，无需第二套创作工作流。新方法必须先进入现有的准入来源和许可证权威，再明确改变目录版本和哈希。UI 接线和认证易梦字节获取仍是分开的后续切片。
