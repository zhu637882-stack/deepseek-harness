# Agent Note: 青木创作历史分页

Status: implemented

[English](2026-09-15-qingmu-writing-history-pages.md) | 中文

## Problem

创作轮次较长时，起点可能移出最近 64 条消息所在的历史页。只读取这一页会丢失运行状态，也无法把空闲且中断的会话送入原生恢复流程。

## Decision

现有创作读取器沿 Host 的历史游标向前翻页，直到遇到轮次边界、本次请求起点或历史末端。游标必须持续向前移动。读取到的完整区间再进入既有运行状态检查与中断恢复。

## Alternatives considered

扩大页长只是更换固定的失败阈值。缺少边界就当作完成，会放出未完成稿。重发提示词可能重复调用模型。

## Consequences

较长的未结束轮次需要更多只读历史请求。完成稿和较短轮次仍只读取一页。恢复使用同一会话，不发送提示词，不改变导航。聚焦测试覆盖仍在运行及已经中断的跨页轮次；不据此验收供应商生成的媒体质量。
