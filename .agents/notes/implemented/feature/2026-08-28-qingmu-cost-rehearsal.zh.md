# Agent Note: 青木零费用演练

Status: implemented

[English](2026-08-28-qingmu-cost-rehearsal.md) | 中文

## 问题

E6-2 必须让小型制作团队在任何付费操作前看清估算、拟议预算占用及其差异。预览必须使用已选 Shot 与 E6-1 能力证据，同时不能让 Harness 变成第二套时长、定价、预算、预留或工作流权威。Gate A 不能提交任务、写正式账本、调用 Provider，也不能暗示已经获得付费生产授权。

## 决策

权威镜头时长、模型目录定价、候选上限与只读 ProviderGate 预算投影只归易梦所有。一个受保护的 GET 绑定项目、剧集、canonical frame、模型、能力、控制项、分辨率、候选数量，以及 E6-1 返回的准确目录、请求、预检和能力快照四个 SHA-256。Harness 还会在浏览器到 Host 的调用中携带刚由 Host 校验过的完整 E6-1 目录投影，使 Host 能再次核验其 canonical bytes，并在接受 E6-2 回执前独立推导 eligibility、价格与候选上限。易梦以整数微元计算全部金额，返回 RFC 8785 JCS 内容寻址回执，并只暴露既有全局预算窗口。项目与剧集额度明确保持 `NOT_CONFIGURED`。

这里的预留只是提案。正式预留 ID 为 `null`；正式预留金额、释放金额、数据库写入和预算账本写入均为零。提交前实际费用不可用。Provider 调用、创建任务、入队、提交、轮询、下载、注册 Webhook 与付费生成权力全部固定为零或 false。不新增持久化或第二套状态机。

现有青木只读适配器独立校验准确字段、身份、E6-1 SHA 绑定、eligibility、主体身份、候选上限、整数公式、预算算术、差额与最终 JCS 回执。任何权力漂移都会失败关闭。驾驶舱只有在用户明确点击并完成一次新鲜的筛选后能力预检后才演练费用。界面展示估算、拟议占用、正式预留零、不可用的实际费用、全局预算、未配置额度、阻塞项与回执 SHA；没有预留、生成或提交控件。

## 考虑过的替代方案

**在浏览器计算费用。** 浏览器中的时长、费率或预算状态可能过期，也会形成易梦无法审计的权威。浏览器只渲染已校验回执。

**创建 Harness 预留账本。** 这会形成第二份财务真相与第二套恢复问题。Harness 不保存预留或预算状态。

**在 Gate A 执行真实预留。** 持久占用属于正式写入，需要 Gate B 的准确授权。E6-2 只报告将要提出的占用。

## 影响

团队可以在不花费资金、不创建任务的情况下，核查确定性的最高估算以及同额拟议占用能否落入当前全局预算窗口。按约定，估算与提案的差额为零；因为尚未正式预留，估算与正式预留的差额仍等于估算。实际费用相对提案的差异与退款值，在未来获得授权的提交生命周期出现前保持未知。

后端测试覆盖认证、不可变镜头时长、快照漂移、声明但格式错误的候选上限、1 微元与半微元整数舍入、JSON 安全整数溢出、预算恒等式、预算阻塞和零副作用。适配器对抗测试会修改 eligibility、费率、候选上限、相关估算/预留/差额字段或预算算术，并重新计算最终 JCS SHA；Host 仍会依据 canonical E6-1 目录或预算恒等式拒绝。客户端测试覆盖显式操作、未选 Shot、准确目录错误，以及旧镜头延迟请求在新回执之后返回但不能覆盖新结果。真实 Loader/Connection 与 Chromium 使用隔离的回环易梦替身，证明点击后只有两次认证 GET、没有上游 POST、出厂青木 overlay、桌面/移动渲染与无密钥 ARIA 输出。该替身不是正式数据库或 Provider。

这些检查不创建或授权真实预留、付费 Provider 调用、正式数据库写入、任务、队列、提交、轮询、下载、Webhook、部署、发布、人工签收、ProviderGate 变更、模型路由变更或 push。

## 验证边界

这只关闭 bounded-local E6-2 零费用演练。生产状态仍是 `UNVERIFIED_FOR_PAID_PRODUCTION`。未来的正式预留必须进入方案 Gate B，并取得准确授权和证据；它不能继承本回执的权力。
