# Agent Note: Native asset design and generation

Status: implemented

English | [中文](2026-09-11-qingmu-native-assets.zh.md)

## Problem

A new project could import a screenplay but its asset workspace only uploaded references. Initial image generation depended on an older script foundation route.

## Decision

Let the native director author editable character, scene and prop cards from the saved screenplay. Save those cards and the director bible atomically into existing project records. Quote the exact image request and queue one confirmed image through the existing budget gate, reservation, worker and media finalizer. Recover task progress after navigation without resubmission. Existing actors and scenes are reused when initializing storyboards.

## Alternatives considered

Another provider client would bypass the shared budget and task recovery. Upload-only creation would leave new projects incomplete. Treating native Markdown skills as old JSON method packages would discard the current director method. The image source retains the actual authored design and method identity without inventing model execution evidence or media approval.

## Consequences

Scene cards keep optional `space` geography in the existing episode design. Individual images keep optional `imageStage` camera, blocking and current prop state. The image request resolves a named scene only within that episode, uses its shared geography when no complete camera-composed view exists, and preserves the current image's staging in both paths. Film direction receives the shared geography but derives shot state from the screenplay and current plan. Legacy saves preserve omitted spatial fields; explicit null clears them. Changing shared layout invalidates pending image quotes and video source hashes. Changing a still-image camera does not redefine film geography. These authored fields guide generation; they do not certify measured dimensions or pixel compliance. The UI exposes both scopes without adding a scene database or automatic media replacement.

Asset cards keep `visualIdentity` (complete entity appearance, structure and layout) separate from `imagePrompt` (the current image or edit request). Image edits preserve the identity used by later scene design. Legacy reads retain their saved description; legacy saves without the new field preserve an existing entity. An explicit identity edit retains selected media and invalidates unsent quotations. With `selfContainedImagePrompt: true`, the director writes all required visible appearance, scale, structure, world exceptions and spatial relationships into `imagePrompt`. Full identity and story rationale remain in the saved design and the immutable task source, without being appended as image instructions. Omitted or false retains legacy composition. Changing this choice invalidates an unsent quote; the UI exposes it alongside the image description.

With a complete-frame description and an enabled camera blockout, the image request uses the project image style, full authored view, current staging and projected geometry. Whole-room inventories and director overviews remain in source context instead of being appended as another visible-object list. The director therefore writes all visible materials, light and tonal intent into the frame description. Without the camera blockout, shared spatial context remains available through the legacy path. The quotation identifies photographic references and the composition image separately; neither technical submission nor projection proves visual fidelity.

The new API requires an authenticated owner and a saved screenplay. Script or design changes invalidate an unsent quote. Generated images remain candidates. Native AI design uses the existing DSH model account; image generation uses the shared Ali budget. The runnable native example and UI tests cover design adoption, quotation and read-only recovery. Provider output quality is checked separately in the film project.

Native asset cards preserve script facts, director inferences and explicit world exceptions. Each image keeps its relevant design basis, view and up to nine ordered project references with exact hashes and reuse instructions; optional regions use original-image pixels. Wan editing receives those image bytes and instructions through the existing task queue. A changed source invalidates the quote. Updating the entity identity retains selected images and flags them for comparison; generating a candidate never replaces them. Authored scene views and requested text are preserved, and overlong requests fail without truncation. Reference previews and quotation do not upload or generate media.

A real screenplay run revealed that unbound writing was incorrectly treated as existing-shot editing and produced contradictory prop transitions. Creation requests now name their stage, the persona scopes shot tools to existing-shot work, and the main director method checks causality in the actual script. Canonical import still occurs through the existing editable-text and preview flow; this change does not claim automatic aesthetic acceptance.

Asset design now consumes effective creation settings at authoring time as well as at image submission. The director-method update declares exact compatible predecessors, preserving existing project contracts and selected media.

The second real writing candidate still rationalized a missing required world exception. Add an optional source-only screenplay revision through a separate native session, reusing draft adoption and recovery. The critic receives original intent and current text, not the writer’s claims about its own correctness.

Earlier Flash writing errors motivated a Pro default. New creative sessions now use the verified DeepSeek V4.1 Flash route; that update does not certify screenplay quality. User selections remain authoritative. Asset refinement receives current unsaved card edits as well as saved source data, so references and world decisions survive a refinement request.

Image framing belongs to each asset design. Film delivery framing can crop a full-body costume reference, while image edits normally inherit source framing. The existing output-size mapping drives a saved optional ratio through quotation to the provider snapshot. Narrative facts remain available to the director. Complete-frame composition keeps other story states out of image instructions after the director has incorporated the required visible facts. Existing designs use auto until explicitly changed.

Scene drafts bind the asset-state SHA as well as the screenplay. Adoption rereads the saved state, so costume or layout edits made during a model run cannot silently reuse its old basis. Asynchronous adoption preserves the draft on a read failure or conflict. The director brief distinguishes an initial still from subsequent actions and requests motivated camera paths without prescribing movement in every shot.

The scene asset method explicitly designs narrative set dressing and intentional negative space. Generic instructions to simplify a composition can otherwise erase meaningful background detail. Asset authoring carries visible decisions into the image description and keeps their rationale in the existing design basis, reusing the existing episode asset design. Runnable method delivery and contrasting scene requests verify the path; generated pixels require separate review.

Non-final browser media can use an expiring signed relative path when no public Provider URL exists. The read adapter resolves that capability against the configured local Writer, so generated images remain visible in the library and region editor. Public Provider reachability checks and authenticated final-media access remain separate.

Real watercolor and monochrome design requests exposed unescaped quotes and a JSON-labelled code block. The asset page recovers the original completed output using jsonrepair only when the transformation inserts quote escapes and preserves all other characters. Existing field validation still owns adoption; missing content is not inferred. Failed native adoption now propagates to the composer instead of reporting success.

Asset cards can save an optional image model without changing the project default. Qwen-Image 3.0 Pro supports up to three ordered references; unsupported region selections and excess references are rejected without removal. Its optional direct prompt extension and thinking are explicit choices, off by default. The quote includes reference-input fees and reserves the highest output tier; the queued request retains the same model, options and dimensions. Switching models invalidates unsent quotes and never generates or replaces media.

Video frame capture reuses project assets and provider-media records instead of introducing a separate continuity store. Source SHA and playback time identify an idempotent capture; decoding precedes the atomic asset write, and concurrent requests converge on one image. Original video and selection remain unchanged. Browser controls and native director tools share this operation. Verification covers actual timed pixels, concurrent recovery, changed source/output bytes and the shipped director tool composition.

Director-plan continuation treats the selected shot as revisioned creative data. Requiring its content to equal the pre-save snapshot blocks the director’s own successful write. The exact saved storyboard revision permits that shot change while script, scene, cast, adjacent shots and reference identities must remain unchanged. The shipped-preset composition projects changed shot content and exercises continuation into draft reconciliation, plus external script, scene and revision changes that still stop continuation.

Qingmu director sessions reuse the stock DSH compaction engine in their preset, with the host token meter. The Web bundle disables global compaction because presets own it; omitting the per-session engine let a real director session exceed the model context limit after a successful draft save. The million-token Flash route also accumulated over 500,000 tokens before reaching a 65% trigger. Its exact-target policy uses an 18% trigger and 32,768-token recent-tail budget, avoiding model-capacity-sized routine history while retaining complete indivisible units. Other routes retain their existing policy. Compaction preserves raw session events and saved Writer content. Rereading current creative sources avoids producing from the checkpoint alone; tool-result pruning is not added because it could hide detailed creative source text. Replacing the loop or resetting the session would duplicate infrastructure or lose continuity. The shipped-preset regression exercises both routes, resumes scoped read tools after actual summarization and checks the unchanged complete saved draft and absence of repeat writes. The distribution default uses the verified V4.1 Flash route while preserving user model choices.

A real native read confused its planning receipt with the generation-source digest and incorrectly reported a current draft as stale. The reference-draft tool therefore computes `sourceAlignment` directly from the two source digests in the same read; missing values remain unknown. The plan receipt stays unchanged for its save contract and explicitly identifies its separate purpose. This avoids delegating deterministic version comparison to prose interpretation or weakening the save guard. Shipped-preset checks cover matching, changed and absent digests without writes.
