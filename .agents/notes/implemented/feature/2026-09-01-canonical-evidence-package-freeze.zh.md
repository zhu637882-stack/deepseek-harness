# Agent Note: 规范证据包恰好一次冻结

Status: implemented

[English](2026-09-01-canonical-evidence-package-freeze.md) | 中文

## Problem

剪辑回传路径已有通过技术检查的母版候选，但缺少由项目 owner 明确触发、冻结规范机器证据包的动作。若由 Host 或浏览器重建证据包，会形成第二权威；若提交成功但响应丢失，也可能重复创建证据包或重复推进证据权威。

## Decision

易梦独占预览、提交、恢复与状态。预览绑定当前发布就绪事实、回传母版技术 QC、来源身份和构建身份。确认只使用一个请求摘要和持久幂等键。跨进程锁配合既有 ChangeSet、outbox、receipt 与 evidence-authority 记录，使重复点击、并发进程、崩溃和响应丢失下的证据包物化及权威推进都恰好一次。

实现直接调用规范 `EvidencePackageService`，不由 Harness 另造证据包。规范读取会重新校验 manifest 和每份字节。既有 Writer 权威的 `qingmu/...` 媒体路径只有在解析到配置 storage root 下的已有文件时才接受；绝对路径、目录穿越、任意前缀、缺失或篡改材料继续失败关闭。

Host 只暴露严格的 loopback 状态、预览和确认合同。它重算规范请求 SHA；遇到不明确响应时只读取原回执，不再次发起构建。制作台先展示机器阻塞，再允许显式确认，并把人工交付签收与发布检查单继续分开保持未完成。

## Alternatives considered

**在 Harness 构建证据包。** 不采用，因为这会复制 Writer 的规范 manifest、存储、证据权威和回执语义。

**响应不明时重试确认。** 不采用，因为网络结果无法证明证据包物化或权威推进是否已经提交；恢复必须读取原幂等回执。

## Verification

Writer 聚焦测试覆盖真实规范就绪判定、规范证据包构建、字节篡改、阻塞投影、重复与并发意图、丢响应恢复、权威推进后崩溃恢复和请求漂移。Host 与 UI 测试覆盖严格 schema、阻塞展示、显式确认、迟到响应安全及原回执恢复。隔离的真实 FastAPI、构建 Host 浏览器路径证明了诚实阻塞状态，且没有 Provider 外呼或用户实例写入。

## Consequences

机器就绪的剪辑回传可生成一个可恢复的规范证据包并只推进一次权威版本。冻结不等于内容批准、发布授权、对外发布或最终人工签收；这些仍是后续显式门禁。
