# Agent Note: 青木能力快照预检

Status: implemented

[English](2026-08-28-qingmu-capability-snapshot-preflight.md) | 中文

## 问题

任何生产请求发生前，生成工作区都需要一份可核查的模型输入、输出、画面规格、一致性控制、互斥规则、成本声明和运行范围。Harness 不能硬编码供应商能力真相，也不能另建第二份目录；互斥策略未声明时，更不能把缺失解释为允许。

## 决策

易梦继续作为模型目录真相的唯一所有者。其只读能力投影将选中的目录档位转换为不可变的 RFC 8785 JCS 快照，并以 SHA-256 内容寻址。它可以在不派发任务的情况下，评估显式给出的模型、能力和控制要求。缺失声明继续作为声明错误显示，所有结果都标记为 `UNVERIFIED_FOR_PAID_PRODUCTION`；投影明确报告供应商调用为零、数据库写入为零且没有付费生成权限。

现有青木易梦读适配器新增一个受保护的回环入口。它使用 RFC 8785 独立重编规范化快照，即使攻击者重算哈希也会拒绝非规范字节；同时根据回显的 dry-run 请求和规范化声明重新计算 eligibility。Host 还会校验一份绑定目录、请求、条目 ID 与决定的预检 SHA，再把类型化数据交给浏览器。它不会把模型事实复制到 Harness 或 IMAGO。

现有制作驾驶舱在「生成与质检」起始位置显示该投影。界面提供目录档位与 SHA、逐模型卡片、声明缺口、互斥规则、快照 SHA、运行范围、成本声明和零权限回执。唯一操作是只读刷新。该界面不能预留、提交、选择、批准、签收或变更路由。

## 考虑过的替代方案

**在浏览器硬编码模型事实。** 这会与易梦漂移，并让 Harness 变成第二份业务真相。浏览器只渲染已校验的易梦投影。

**在 Harness 或 IMAGO 保存另一份目录。** 这会新增第二个所有权界面，并制造不必要的对账问题。IMAGO 方法以后可以消费已冻结快照，但两层都不拥有来源声明。

**把缺失互斥规则视为能力不受限。** 缺失不是兼容性的证据。投影保持未验证状态，并显示缺失声明。

## 影响

后端测试使用临时目录，证明跨运行时快照身份确定、显式冲突控制会被拒绝、真实 FastAPI 认证边界成立、错误声明会失败关闭且没有副作用；同时证明当前未声明互斥规则的正式目录保持不完整，不会被补入虚构规则。适配器测试会拒绝重算后的非规范字节、带匹配伪造预检哈希的 eligibility 篡改、请求漂移、权限漂移、身份漂移、错误控制值和非回环访问。

客户端测试覆盖显示、刷新、适配器拒绝、取消及驾驶舱集成。真实 Loader/Connection 与 Chromium 组合使用隔离的回环易梦替身，证明出厂青木 overlay、带认证的纯 GET 请求、可见互斥规则、版本哈希、桌面/移动布局和无密钥 ARIA 快照。该替身不是正式供应商或数据库。

这些检查不授权付费生成，不验证真实供应商账号，不修改 ProviderGate 或模型路由，不批准内容，不部署生产，也不 push 分支。

## 验证收口

仓库既定生成器现已登记易梦当前全部 309 条显式后端路由。外置青木 Harness 路由使用精确 method + path 条目，不使用命名空间通配；metadata override 遇到未知字段或不存在的后端路由会失败关闭。普通与完整 registry 检查均通过；易梦聚焦组合 24/24、完整前端合同 309/309，冻结依赖锁仍为当前状态。独立 Reviewer 裁决 PASS，P0 至 P3 均为 0。

这只关闭 bounded-local E6-1 能力目录切片。E6-2 的估算、预留和差异仍是独立工作；不代表 queue、submit、poll、download、webhook、真实 Provider、费用、正式数据库或承重路由变更获准。
