# Agent Note: 从精确已选参考建立首个 PromptIR

Status: implemented

[English](2026-08-31-qingmu-first-prompt-ir-bootstrap.md) | 中文

## Problem

既有 PromptIR 编辑器必须以当前 Ready 版本为基础，因此新场景若不借助 fixture 或伪造基线，无法进入 canonical 提示词工作流。直接创建 Ready 会把机器产生的草稿与项目 owner 的版本选择混为一件事；要求所有已选元素参考则会过度约束只展示环境的建立镜头。

## Decision

对于真实 Ready 分镜帧且尚无 PromptIR 血缘的情况，青木制作台现在提供两步首个 PromptIR 路径。易梦从当前剧本、分镜帧、精确已选且通过资格检查的参考、元素 profile 和实际落盘字节构建一份绑定修订与 SHA 的上下文。必需参考集合由镜头本身决定：环境必需，只有当帧的对白或动作绑定用到人物、道具时才要求它们。

IMAGO 用带版本、带签证且零执行的方法编译该上下文，得到五个可编辑提示词字段和稳定排序的参考列表。易梦校验方法投影，并在一个原子事务中写入唯一 Draft、其结构参考包、ChangeSet、outbox 事件、agent-run 谱系和命令回执。独立的认证 owner 命令在重新核对上下文、方法、内容和参考哈希后，才能把该精确当前 Draft 提升为 Ready。选择还必须携带绑定该 Draft 的短时 Writer 签名 challenge，以及 Host 针对本次新编译投影签发的新鲜度证明；旧方法证明本身不能完成选择。Ready 只表示当前选中的提示词版本，不推断权利核验、正式一致性、内容批准、生成权限、发布或人工签收。

浏览器只保存有界的恢复坐标和哈希。Draft 或选择结果不确定时，查询原幂等回执，不创建第二个提示词、参考包或选择事务。既有多帧 PromptIR 创建和基于已有 Ready 的编辑继续沿用原合同。

## Alternatives considered

**编辑前插入空 Ready PromptIR。** 这会伪造前代，并使方法首次产生的内容看起来已经被选定。引导路径先写 Draft，再分离 owner 选择。

**要求项目中的所有参考。** 这会把画外人物和道具绑入建立镜头。必需参考由当前帧派生，同时所有绑定仍保持精确且失败关闭。

**在 Harness 或浏览器存储首个提示词。** 这会建立第二业务权威，并破坏重启恢复。易梦继续是唯一可变账本；Harness 只校验、展示并调用其命令。

## Consequences

新场景现在可以经一次真实、可恢复的 Draft 到 Ready 转换进入既有 PromptIR 编辑器，不调用 Provider，也不伪造批准。剧本、分镜帧、profile、已选参考、落盘字节、资格、权利记录、方法或内容的任一漂移都会阻止提交或选择。更严格的边界带来一次明确 owner 操作，并使包含人物或道具的镜头在精确必需参考存在前持续阻塞。生成、QC、发布和人工内容接受仍属于之后的独立操作。
