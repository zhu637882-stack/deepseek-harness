# Agent Note：青木同一镜头的问题记录与回执恢复

Status: implemented

[English](2026-08-27-qingmu-shot-finding.md) | 中文

## 问题

同一 canonical Shot 需要审核者明确填写的问题记录。既有视频缺陷缺少完整 Finding 合同，不能靠推断成为新的批准或返修权威。POST 响应丢失不能引发第二次写入，也不能因为当前选中视频变化而丢掉原回执。

## 决策

仅由易梦通过既有 ChangeSet、回执和 outbox 事务保存 Finding。Host 重读已选视频主体，编译当前 IMAGO 方法，校验固定 18 个来源哈希，并对精确主体与方法出具证明。Reviewer 权限由易梦复核，不由浏览器表单授予。作者八字段必须明确填写并原样保留，包括重复引用；与 Python 一致的文本校验不改写 canonical ID 或作者原文。

驾驶舱在既有共享 Shot 下增加问题表单和历史。沿用同一帧 ID 与显示镜头号，核验业务分镜修订，在选择、来源或适配器变化时隔离迟到响应。责任岗位和严重度初始为空。普通界面使用专业岗位名，内部 Stage 编号只在可展开的记录详情中显示。

发起一次 POST 前，浏览器同步持久化并读回八字段恢复标记，仅保存作用域、幂等键以及主体、作者输入和方法哈希。结果未知则保留标记。显式恢复只按原坐标 GET；即使当前媒体或方法不可用，经核验的原回执仍可清除标记。找不到回执则继续保留。存储范围仅为当前标签页 sessionStorage，不是跨浏览器持久化。

记录始终产生 OPEN Finding，不批准内容、不改变选择或质量、不解锁、不路由任务、不执行返修、不调用 Provider。历史绑定仍为历史。Harness 只持引用，不形成第二业务账本或项目 DAG。

## 考虑过的替代方案

**自动升级旧缺陷。** 这会虚构责任、严重度和审核者意图。既有审核证据继续只读，新的 Finding 必须明确填写全部作者字段。

**重试结果未知的 POST，或按当前媒体恢复。** 前者有第二次写入风险，后者可能丢失旧事务。恢复只查询冻结的幂等键与主体坐标。

**全部使用普通 JavaScript trim。** 它的空白字符集合与 Python 权威合同不同。局部 Finding 校验与该合同对齐，同时保留原始 Unicode 和码点长度限制。

## 影响

新增本地管道分别经过真实 Core 编译、易梦临时 SQLite，以及真实 Host/Chromium 加隔离 HTTP 上游验证。这些是互补的本地检查，不是正式生产端到端结论。正式 schema/API 仍需显式开启。实际 Stage/LSU/批准锁权威与可执行返修仍是独立的未完成工作。不隐含付费生成、正式数据库启用、人工签收或 push。
