# Agent Note: 青木原生导演读取

Status: implemented

[English](2026-09-07-qingmu-native-director-reads.md) | 中文

## Problem

把 DSh 会话绑定到 Writer 镜头只记录其身份，不会把镜头创作输入交给模型。 方法注册和来源哈希同样不提供 IMAGO 的真实导演方法正文。助手可能看似接通， 却没有提出有效建议所需的依据。

## Decision

在导演上下文桥中增加可选、限定作用域的 `model-tools` 入口。它通过现有 Host 命令适配器读取绑定的 Writer 快照，通过 IMAGO 方法适配器读取完整 C 或 C5 Skill 正文与直接参考。C5 的第四参考可用固定资源 ID 追加读取。模型不能选择 其他会话、对象、文件路径或方法根目录。

复用原生工具注册表与 Agent 循环。普通工具结果把准确返回的 JSON 保存在原有 会话日志并送入下一轮模型请求；绑定事件仍仅记录日志。每次读取前刷新上下文， 切换作用域后拒绝迟到结果，失败时保留手工编辑。来源哈希标识方法字节， 不授予业务或创意批准权。

Writer 仍是业务真源，Core 仍是方法来源。不复制项目，不新增数据库、控制器、 Agent 循环或生产预设。本次实现的是源码级读取能力，不等于部署或完整创作流程。 IMAGO 用于场景意图、表演、调度、连续性和声画推导，不被缩减成提示词格式库。

## Alternatives considered

**把全部技能注入每轮系统提示词。** 这会增加 token，并掩盖实际请求了哪份方法。 显式、完整的工具响应可以回放，也允许 Agent 按需补读必读参考。

**开放通用文件读取或全部 Writer 命令。** 这会在读取边界尚未验证前扩大权限。 固定方法 ID 与会话绑定能提供所需内容，无须业务变更或任意文件访问。

**再建一套编排循环。** DSh 已经持久化工具调用与结果。平行循环会重复恢复机制， 使模型输入更难检查。

## Consequences

显式启用的 Agent 能收到真实 Writer 上下文与 IMAGO 方法正文。根作用域和普通 Agent 不会获得这些工具。文本上下文不证明图像质量或全剧理解；缺失事实保持未知。

来源加载器限制文件读取并拒绝指向根外的符号链接；部署仍须在读取期间保持方法树 稳定。512 KiB 的来源包可能超过消费端默认 256 KiB 的序列化响应上限，此时失败， 不截断内容。完整方法正文只在请求时消耗 token。

Loader 预设 Agent 循环测试使用脚本化外部响应，核验下一轮模型输入与日志冷恢复， 不能证明真实提供方质量。建议采用、Writer 持久化、PromptIR、生成与生产启用， 仍须各自接通业务链并验证运行时。
