# Agent Note：青木准确阶段工件决定

状态：已实现

[English](2026-08-28-qingmu-stage-artifact-decisions.md) | 中文

## 问题

通过机器校验的阶段工件登记有意不授予任何业务权威。E5-5 检查点仍需要一项由独立自然人作出、绑定准确当前记录的决定，并且在上游工件、锁、规则或哈希漂移时失败关闭。若在 Harness 复制这项权威，就会形成第二套生产状态机。

## 决策

既有易梦命令适配器在阶段工件路由族中增加 `commitStageArtifactDecision` 与 `recoverStageArtifactDecision`。决定请求接收一次明确的 `approve`、`reject` 或 `request_changes` 意图与理由、准确的当前工件记录修订/SHA、工件修订/SHA、主体 SHA 和完整准确工件。它拒绝调用方提供的方法字段。受信 Host 调用当前已加载的 `stageArtifactMethod` 能力，校验当前阶段定义、规则摘要、主体与记录绑定、投影 SHA 和 Host 专属 HMAC 证明，然后只转发一次 POST。它绝不接受浏览器提供的 actor、岗位、自然人身份或 session 字段。

易梦仍是唯一权威。它在认证事务中派生审核人和会话，要求项目配置的 approver 功能，证明生产者与批准者是不同自然人，并把决定绑定到不可变登记记录。它重新计算当前已批准的上游记录及准确批准/锁事件 SHA。来源、规则、依赖、锁、记录、工件、修订或 SHA 任一漂移都会失败关闭。只有依赖快照已核验的批准，才能让准确工件变为可用，并激活该登记阶段定义声明的锁。`reject` 与 `request_changes` 都不授予可用性或锁权威。

每个目标的追加顺序都由纳入哈希、连续递增的 `decisionOrdinal` 保护，因此数据库行顺序或时钟回拨都不能复活较早的批准。`probeStageArtifactAuthority` 接收准确记录与工件，受信 Host 随后在内部调用当前已加载的 Method 能力，并只把这份新鲜证明带到易梦只读 `/authority-probe`。易梦在该证明下重新计算规则、依赖和锁，并返回紧凑的当前权威结果。Harness 还会按当前阶段定义核验准确锁。普通工件 GET 只用于历史回读；没有新鲜签名规则时会失败关闭。

持久决定与命令回执复用易梦现有的 ChangeSet、domain-outbox 和 command-receipt 三本账。没有新增表、schema 迁移、DAG 或第二套业务状态机。Harness 只校验返回的权威声明，既不计算也不持久化。计划封存、推断人工签收、返修执行和 Provider 调用必须保持 false 或零。

结果不确定的决定 POST 绝不重试。恢复只使用原始阶段坐标、工件记录修订/SHA 和幂等键，向 `/decision-command-receipt` 发送一次无正文 GET。即使今天的 HMAC 密钥或历史 bearer 会话已经变化，Harness 仍会重新校验原始准确回执。

## 考虑过的替代方案

**在 Harness 计算依赖与锁权威。** 这会把插件控制面变成与易梦竞争的生产真相，违反易梦唯一归属。

**把阶段工件登记视为批准。** 机器校验只证明确定性结构和方法合规，不能替代经过认证的独立自然人决定。

**决定响应丢失后重新提交。** 只有查询原回执，才能在不追加业务写入的前提下确认第一条命令的结果。

## 影响

适配器聚焦测试覆盖准确 schema、三类决定、自批拒绝、受信当前 Method 执行、历史证明重放拒绝、规范指数数字、HMAC 绑定、已核验依赖快照、准确声明锁输出、当前权威探针、字段及血缘变异失败关闭、凭据反射和只读 GET 恢复。真实 Cordis Loader/Connection/WebServer 组合调用当前 Core 编译器，向隔离的易梦 HTTP 双替身发送登记、决定与权威探针请求，证明 Method 能力关闭时决定与探针都会失败关闭，故意丢失决定响应，轮换 HMAC 密钥和 bearer 会话，再恢复原回执，并证明不会出现第二次决定 POST。易梦服务与 API 测试覆盖持久三账一致性、独立自然人、时钟与行顺序变异下受保护的决定顺序、当前规则/上游/锁权威、漂移失效、幂等和只读恢复。

本检查点不增加 UI、LSU 计划封存、返修执行、自动名称映射、第二套 DAG、Provider 调用、正式数据库迁移、部署或 push。
