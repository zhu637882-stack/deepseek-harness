# Agent Note: 青木导演素材设计保存与出图询价

Status: implemented

[English](2026-09-17-qingmu-director-asset-design-save.md) | 中文

## 问题

在前期制作阶段，原生导演只能读取已保存的剧集素材设计（`qingmu_read_asset_design`），不能写入。人物、场景、道具的视觉合同在别处产生，导演的 production-design、character-asset、scene-asset、prop-asset 技能对后续出图所依据的设计没有影响。导演也看不到一次素材出图实际会发送的提示词，因此身份合同写得不充分只能在付费生成之后才暴露。

## 决策

两个工具与现有参考稿工具挂入同一个 `qingmuYimengRead` 注入块，在剧集范围的创作请求期间可用。

`qingmu_save_asset_design` 通过现有 `saveAssetDesign` 命令适配端点保存一份完整的创作设计。会话的创作请求固定项目与剧集；模型只提供 `design` 与观察到的 `expectedStateSha256`。参数仅限这两个键，且设计在发出任何请求前校验：只允许 `assets`、`director` 与可选 `world` 键，`assets` 必须非空，每个素材的 `kind` 必须是 actor、scene 或 prop，且 `name`、`imagePrompt`、`visualIdentity` 非空。其余业务字段以后端为权威，包括后端会保留的省略字段。状态冲突拒绝保存并指示重新读取后重放编辑；冲突的保存不写入任何内容。回执报告新的状态与剧本哈希，并确认零次 Provider 调用。保存不是价格确认、付费生成、媒体选定或批准。

工具描述写入了出图 API 没有独立负向提示词通道这一内容纪律：`visualIdentity` 用正向表述覆盖技能要求的维度，`imagePrompt` 描述本张图的画面与状态，`designBasis` 记录推理而非绘图清单。禁止事项绝不写成正面 prose，因为这样的措辞本身会被内容扫描。

`qingmu_quote_asset_image` 以零付费试算返回后端为某个已保存实体编译的出图请求：最终提示词原文、模型、能力、引用、目录价与询价哈希。它是无请求体的 GET，不执行任何生成。存在 `compositionReference` 时剔除其 `imageUrl` 数据地址——其中可能携带数 MB 像素，不得进入模型上下文。两个工具合成一个核对闭环：保存设计、询价实体、检查编译后的提示词、修正设计、再次保存——全部发生在任何付费步骤之前。

## 否决方案

**给工具或设计增加负向提示词字段**被否决，因为 Writer 的出图提交路径有意不设负向提示词通道；把禁止事项写成正面 prose 本身会被内容扫描。所需纪律放在技能与工具描述中，并由询价读取核对编译结果。

**允许模型提供范围或实体坐标**被否决，与所有原生工具一致：范围来自被消费的创作请求，询价只接受已保存设计必须包含的实体 id。

**把这两个工具加入必需就绪集**被否决，因为现有 `qingmu_read_asset_design` 同样不在其中；素材设计仍是可选的前期阶段，不是镜头工作的闸门。

**单独的草稿—确认两段流程**被否决，因为命令适配器的乐观状态哈希已提供与冲突回读配合的恰好一次语义，与参考稿保存使用的模式相同。

## 影响

导演现在可以拥有它后续出图所依据的素材设计，使用与工作区相同的持久化、冲突与恢复路径。提示词不充分在零成本的询价步骤暴露，而不是在付费之后。这两个工具不改 Writer 代码、不加生成路径、无法派发付费运行：询价是 GET，付费的 `generateAssetImage` 端点不向原生导演暴露。

## 测试

`reference-video-tools-composition.spec.ts` 通过出厂导演预设与真实命令适配器，对一个有状态的假 Writer 驱动这两个工具。保存按精确的预期状态哈希与设计发出 POST，报告新哈希，且从不调用生成或询价端点；过期的状态哈希被拒绝且不写入；注入范围、缺少 director 对象、缺少身份合同、缺少画面描述、未知素材种类分别在发出任何请求前拒绝；单镜头绑定拒绝保存。询价通过纯 GET 返回包含已保存画面描述的编译提示词与格式正确的询价哈希，未知实体被拒绝。原生导演示例快照记录了这两个工具进入出厂预设的作用域工具列表。
