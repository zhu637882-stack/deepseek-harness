# Agent Note: 分离 RC1 证据、内容审看与发布签署

Status: implemented

[English](2026-09-01-rc1-content-review-authority.md) | 中文

## Problem

规范证据包只能证明机器事实，不能表达项目 owner 对整集终稿的创作判断。若复用组织发布签署承载该判断，会混合三种权威，并把自动生成的机器证据包误呈现为人工内容接受。

## Decision

易梦独占一份不可变的集级终稿内容决定日志。自然人项目 owner 只有在决定请求精确绑定当前终稿资产、落盘字节、严格核验、RC1 包、manifest、发布权威版本并完成全片播放后，才能接受当前终稿或退回修改。接受还必须完成具名的画面、声音与连续性检查，并进行第二次明确确认。

RC1 包是独立的规范证据冻结，不继承既有 Pre-RC 包身份。发布就绪独立投影内容决定；当前绑定未接受时，组织发布签署保持阻塞。既有生产终稿验收入口在 RC1 存在时桥接到同一日志，因此不能建立竞争性的接受权威。

Host 只代理严格鉴权的状态、决定、媒体和证据合同。媒体与 ZIP 读取会重新校验当前 ID 和 SHA，并支持字节范围。写入结果不明时只恢复原回执，不再次提交决定。制作台把机器证据、个人内容审看与组织发布签署展示为三张独立卡片；自动化可以提交退回，但绝不能提交接受。

## Alternatives considered

**把 RC1 证据视为内容接受。** 不采用，因为确定性的包完整性不能证明创作审看或自然人意图。

**在 Harness 或浏览器状态保存接受。** 不采用，因为项目身份、不可变业务决定、回执和发布权威均由易梦拥有。

**复用组织发布签署作为内容决定。** 不采用，因为组织授权与项目 owner 的整集判断具有不同的执行者、证据和后果。

## Verification

Writer 聚焦测试锁定 owner 与自然人鉴权、精确来源绑定、全片播放、具名检查、幂等恢复、发布就绪阻塞及旧验收桥接。Host 与 UI 测试锁定严格 schema、Range 转发、单次写入恢复、三卡展示，以及自动化绝不接受。隔离浏览器路径使用真实 FastAPI 与构建 Host，且不调用 Provider、不写用户实例。

## Consequences

RC1 机器完整性、人工整集判断与组织发布授权可被分别审计。接受可恢复，且不能在来源漂移后静默沿用。该决定在发布签署前新增一道人为门禁，但不代表已经发布、组织批准或完成整机产品验收。
