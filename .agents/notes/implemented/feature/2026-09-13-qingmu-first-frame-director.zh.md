# Agent Note: 青木首帧导演输入

Status: implemented

[English](2026-09-13-qingmu-first-frame-director.md) | 中文

## Problem

镜头可能同时继承旧世界布局推导和当前共用场景。原生导演可以协调视频来源，却无法读取真正的首帧图片准备结果。

## Decision

通过原生命令适配器和绑定当前镜头的导演工具，开放既有 Writer 拍摄预览。工作台提供可编辑的首帧整理要求。主导演方法读取完整当前来源，保存协调后的逐镜设定和独立首帧，再核对实际编译提示词。工作引用保留准确编号、哈希与用途。来源时效、设计保存、生成和采用继续由原模块负责。

## Alternatives considered

按关键词删除世界文字会丢失创作意图。另建编译器会偏离实际提交的请求。共用预览保持一条生产路径，由导演判断语义。

## Consequences

导演无需付费生图即可核对真实输入。旧项目沿用原来源和保存路径，修改保留其他导演字段。准备可能保留本地预览文件，不创建媒体任务或授予批准。语义协调和像素效果需要分别验证。

现场验证发现技能正文更新后遗漏兼容目标更新。来源清单已覆盖经核对的历史版本和上一发布版，既有兼容回归检查全部当前目标。规划读取失败在拍摄助手中直接显示并提供只读重试，保留输入，恢复前不能发送。

后续现场检查发现通用 HTTP 409 隐藏了图片模型输入上限。适配器现传递有边界、脱敏的具体原因，可编辑要求让导演协调重复描述而不截断创作设计。拍摄选择同时按当前镜头与场景绑定覆盖全部场次，不依赖规划编辑器保留的选择。
