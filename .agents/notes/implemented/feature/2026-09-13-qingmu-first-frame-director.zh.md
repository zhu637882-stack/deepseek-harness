# Agent Note: 青木首帧导演输入

Status: implemented

[English](2026-09-13-qingmu-first-frame-director.md) | 中文

## Problem

镜头可能同时继承旧世界布局推导和当前共用场景。原生导演可以协调视频来源，却无法读取真正的首帧图片准备结果。

## Decision

通过原生命令适配器和绑定当前镜头的导演工具，开放既有 Writer 拍摄预览。工作台提供可编辑的首帧整理要求。主导演方法读取完整当前来源，保存协调后的逐镜设定和独立首帧，再核对实际编译提示词。工作引用保留准确编号、哈希与用途。来源时效、设计保存、生成和采用继续由原模块负责。

## Alternatives considered

按关键词删除世界文字会丢失创作意图。另建编译器会偏离实际提交的请求。共用预览保持一条生产路径，由导演判断语义。

## Consequences

一次真实23段广告的完整导演稿超过了旧有96 KiB规划提交上限，尽管每个镜头的设计均合法。整场初始化现接受最多4 MiB规范JSON，仍在已有命令传输上限之内；64镜头、每份导演计划64 KiB以及单镜编辑上限保留。保存与GET回执恢复共用相同校验和摘要。Loader浏览器RPC快照覆盖超过旧限制的完整中文场景；聚焦检查验证超大的整场、单镜计划及编辑在传输前被拒绝。

导演无需付费生图即可核对真实输入。旧项目沿用原来源和保存路径，修改保留其他导演字段。准备可能保留本地预览文件，不创建媒体任务或授予批准。语义协调和像素效果需要分别验证。

现场验证发现技能正文更新后遗漏兼容目标更新。来源清单已覆盖经核对的历史版本和上一发布版，既有兼容回归检查全部当前目标。规划读取失败在拍摄助手中直接显示并提供只读重试，保留输入，恢复前不能发送。

后续现场检查发现通用 HTTP 409 隐藏了图片模型输入上限。适配器现传递有边界、脱敏的具体原因，可编辑要求让导演协调重复描述而不截断创作设计。拍摄选择同时按当前镜头与场景绑定覆盖全部场次，不依赖规划编辑器保留的选择。

素材报价对 HTTP 409 和 422 使用同样受限的原因传递。现场一次场景修图使用了模型不支持的参考框选，具体修正提示却被隐藏。适配器保留最多 2048 个字符的脱敏字符串，不显示结构化校验内容或服务器错误，也不重试。Loader 浏览器 RPC 快照覆盖该拒绝且不付费生成；聚焦用例覆盖长度、脱敏和无关状态码。

实际修正轮连续保存两次后拦住了自己的预览：绑定仍是第一次保存的上下文，刷新前检查却要求第二次的版本。刷新前现仅接受本轮已接收请求的成功回执连续链；刷新后要求最新版本。组合回归覆盖预览被拒后连续两次保存、最终回读过期，以及无关剧本、场景或分镜变更。

第二个项目又暴露了读回失败：Writer 中相同的 imagePrompt/imagePromptCn/visual 以及扁平机位、走位副本超过内联结果容量。模型视图现通过 JSON 指针标出完全相同的副本，保留完整 directorPlan 和所有不同值，原始 Host 回执不变。丰富设计回归跨过旧输出上限，重开完整稿后再保存其他决定，起始图不丢失。独有内容超过剩余容量仍明确失败；这是无损去重，不是无限上下文。
