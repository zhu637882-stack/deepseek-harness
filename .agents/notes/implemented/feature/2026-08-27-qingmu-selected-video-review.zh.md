# Agent Note: 青木已选视频审核证据

Status: implemented

[English](2026-08-27-qingmu-selected-video-review.md) | 中文

## 问题

连续性面板尚未展示当前选中视频已有的缺陷记录。把候选状态或素材时间戳复制成新批准模型会丢失来源身份，也可能提升过期或未选中证据。

## 决策

通过 Host 只读适配器复用易梦现有 video-candidates GET。只接受三个 ID，核对主体、选择、状态、素材 SHA 和通过条件一致性后，投影唯一当前选中素材的原审核。旧版缺失保持明确，剥离媒体 URL、费用和素材时间戳。当前媒体与帧绑定仍由易梦负责；文件不可用时的存储 SHA 不证明当前字节。

在连续性旁使用同一 canonical Shot 展示元数据。保留原缺陷、零与分数时间点、null 时间点和备注；审核修订必须对应可见剧集修订。取消与请求身份隔离刷新、来源变化、镜头切换和关闭。唯一控件重新读取来源。

## 考虑过的替代方案

**新增易梦 API 或审核存储。** 已有端点提供所需来源事实，无需修改生产运行时或 schema。

**把已通过候选或机器质量提升为签收。** 只展示唯一已选素材。既有审核和机器例外记录不授予独立青木或 IMAGO 批准、认证审核角色或自动返修。

**加载媒体以建立新审核流程。** 本切片仅连接已有证据，不新增媒体加载、批准按钮或 Provider 操作。

## 后果

Host 与 UI 测试覆盖原状态、旧版缺失、准确绑定和迟到响应。易梦测试对 query-only 临时数据库及真实本地样例字节执行现有 API。Chromium 验证共享选择和只读行为，不接触正式数据或生成媒体。正式 Finding、责任、锁和生产签收仍是独立工作。
