# Agent Note: 青木显式制作单元范围绑定

Status: implemented

[English](2026-08-28-qingmu-production-unit-bindings.md) | 中文

## 问题

返修准备需要将易梦已有镜头组与制作单元显式关联。展示用镜头序号、问题记录或列表位置都不能代替该关联。写入结果不明时，也必须能查回原回执而不重新提交。

## 决策

现有读插件暴露易梦原生镜头组来源及当前或历史绑定。镜头主键始终是权威身份，稀疏的展示序号原样保留。方法插件重新读取指定镜头组，调用当前 IMAGO 无状态方法，校验固定九份规则来源和当前定义，再次回读来源与规则后才签发证明。浏览器只提供项目、单集和镜头组坐标。

命令插件仅发送一次显式绑定请求，使用来源 SHA 与绑定修订号/SHA 进行比较后写入。易梦负责已有 ChangeSet、outbox 和回执的同一事务。POST 结果不明时不重试。恢复仅按原镜头组、单元、来源 SHA 和幂等键执行 GET；读取旧回执不要求当前方法签名密钥或原登录令牌仍然有效。易梦仍校验当前权限与原操作者。

这只是三个现有插件的扩展，没有新增运行时或账本。读能力缺失时停止方法准备。范围绑定不封存制作计划，不创建可执行工作单，不批准阶段或内容，不释放锁，不执行返修，也不调用供应商。

既有镜头工作区要求明确选择镜头组、填写单元 ID，并确认仅登记范围。在唯一一次 POST 前，先可靠保存十一字段、非秘密的恢复标记。当前镜头、来源或方法不可用时，仍按原坐标恢复。只有回执核验后才可条件清除标记并重读权威数据，不直接用回执生成界面绑定记录。Finding 详情复用已核验列表，不另发请求，并匹配原问题的项目、单集、镜头主键、展示序号、镜头内容 SHA 和分镜修订。

## 考虑过的替代方案

**按镜头序号或问题记录推断单元。** 这会在缺少原生镜头组与负责人显式操作的情况下制造制作范围。因此必须使用已有镜头组及其镜头主键。

**丢失 POST 响应后用新命令重试。** 这会丢失原事务边界。独立恢复入口只查询冻结的原命令坐标。

**另建 IMAGO 项目状态。** 本次融合需要专业方法证据，不需要第二个业务进度所有者。此处 IMAGO 保持无状态，绑定事务仍归易梦。

## 影响

Host 测试覆盖错误合同、Unicode、来源与方法变化、过期比较条件、历史回执恢复、取消、超时与响应大小限制。真实 Loader/Connection 测试连接当前 Core 和隔离 HTTP 上游，验证写入响应丢失、原回执恢复及读插件卸载/恢复。该 HTTP 上游是测试替身，不是正式数据库。另有 Core/易梦临时 SQLite 证据覆盖后端事务。

客户端测试还覆盖明确确认、存储失败、标记比较后清除、错误证据、迟到响应、关闭及共享列表失效。真实 Chromium 场景通过既有 Host 和当前 Core，验证显式登记、POST 响应丢失、页面重载、来源不可用时查询原回执，以及随后权威回读。桌面和移动端检查覆盖这一区域及 Finding 的只读关联。其易梦上游仍是隔离 HTTP 测试替身。

这些检查不代表正式启用、计划封存、独立批准、人工签收、部署或付费生成。此检查点不包含 push。
