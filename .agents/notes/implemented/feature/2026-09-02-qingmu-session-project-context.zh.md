# Agent Note: 青木会话绑定的项目上下文与导演回放

Status: implemented

[English](2026-09-02-qingmu-session-project-context.md) | 中文

## 问题

现有青木适配器能够读取当前易梦生产事实并提供不可变的 IMAGO 导演回放方法，但 DSh 没有可持久恢复的标识来说明一个会话正在讨论哪个项目对象。调用现有导演建议命令并不合适，因为它会写入易梦 work order。只在浏览器或进程内变量中保存选择会在重启后丢失，而把项目内容复制进 Harness 会创建第二个业务真源。

## 决策

`@deepseek-ai/dsh-experimental-qingmu-project-context` 在现有 DSh 会话日志中记录一个完整值 `qingmu/project-context` 事件。该值只包含项目、剧集、Scene 和 Shot 坐标，以及精确的剧集、故事板和 Scene revision 与故事板、Scene、Shot 和上下文 SHA-256 标识。最新事件就是当前绑定，因此切换 Shot 和恢复已停止会话使用同一个确定性折叠过程。本功能不创建新的持久化系统或业务台账。

每次建议都会重新读取标准化的易梦工作流。revision 或 SHA 发生差异，或者成功读取后发现 Scene/Shot 已删除或移动时，适配器会追加 `stale` 状态，并在加载 IMAGO 方法前返回 `refresh_required`。绑定保持新鲜时，适配器只加载现有零权威的 `directorReplayMethod`，并为绑定的 Shot 构建确定性的变更集草案。文本建议和视觉建议分别保留其声明的输出 schema。响应包含当前对象、精确的方法与上下文哈希、显式差异、影响范围和负权威声明。会话只保留精简哈希回执，不保留建议或项目正文；回放校验会重新计算每个绑定标识，并把每条回执关联到它之前的当前绑定。

私有 loopback 处理器只拥有 `bind`、`current` 和 `suggest`。它既不导入易梦命令适配器，也不修改启动器、状态、导航、认证、代理、运行时路由、创建设置、ProviderGate、发布、Stage 或费用约定。本切片没有应用组合包加载该包。方法能力缺失时仍可继续人工工作。

## 考虑过的替代方案

**复用现有导演建议命令。** 否决，因为该路径会创建易梦 work order；本切片必须在不写入业务状态的情况下证明上下文和回放建议。

**把选择持久化到第二个青木数据库或浏览器存储。** 否决，因为重启恢复已经属于 DSh 会话持久化，另一个存储会引入竞争权威和漂移。

**把当前项目快照复制进会话日志。** 否决，因为会话需要坐标和新鲜度标识，而不需要复制业务内容。使用时从易梦读取新鲜内容。

**把 IMAGO 或模型不可用视为会话阻塞。** 否决，因为回放建议只是辅助信息。人工创作工作仍然可用，并且这个确定性切片不需要提供方调用。

## 后果

DSh 会话可以恢复它正在讨论的精确青木对象，显式切换 Shot，并在输入未变化时重现同一份 SHA 绑定建议。源数据漂移会在建议构建前关闭路径并要求显式刷新。本包不获得批准、选择、生成、预算、提供方或业务写入权威。代价是任何相关 revision 或 SHA 变化后，调用方都必须再次绑定；后续应用组合也必须有意加载这个可选包，才能使用其 RPC。

## 测试

包测试使用真实的事件溯源 `Session` 实现，并注入只读工作流与方法处理器。测试覆盖精确绑定、确定性回放、Shot 切换、revision/SHA 和 Shot 删除失效、损坏绑定/回执拒绝、取消、精简回执、零权威字段，以及方法不可用时继续人工工作。JSONL 持久化往返会先重新挂载后端，再恢复精确绑定。包类型检查、仓库约束、文档门禁和 lint 覆盖新的工作区与事件声明。
