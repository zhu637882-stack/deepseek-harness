# Agent Note：青木 DSh 默认入口与保存同步

Status: implemented

[English](2026-09-02-qingmu-dsh-entry-sync-c.md) | 中文

## 问题

本地 DSh 入口原来会打开通用 Harness 界面，青木驾驶舱保持关闭。场景规划可能从隐式首个项目或剧集开始；iframe 内保存成功后，也不会告诉外层六阶段界面应刷新并定位到哪一个准确场景和镜头。

## 决策

只有 URL 提供准确项目与剧集时，嵌入入口才有效。驾驶舱直接打开导演工作区；canonical 初始化以及每次保存/恢复校验都保留完整的项目、剧集、场景、镜头、故事板、context 与方法作用域。作用域缺失或错配时失败关闭，不用集合索引代替身份。

场景规划 replay 继续明确为参考建议演练。逐项采纳仍然经过既有新鲜度检查、差异预览、明确确认、回执恢复与权威回读。人工编辑继续使用同一保存路径，并且始终保留。

权威回读完成，且新的导演 context 绑定证明保存后的作用域后，iframe 才向一个已校验的回环地址父页面发送 `deepseek.dsh.qingmu-scene-planning-saved.v1`。整值消息包含稳定 event ID、准确对象坐标、保存后 context SHA、回执、定位目标，以及人工权威或完整的方法绑定采纳证明。外层 Host 可据此去重、刷新 canonical 投影，并定位到同一场景与镜头。

一个有界、无秘密的 `localStorage` outbox 只保留准确项目与剧集的最新通知。页面重载或进程重启后，只有当前 Session 绑定同时匹配消息对象坐标与 context SHA，才允许重放。无效存储、陈旧 context、迟到结果、跨作用域消息、顶层页面使用、不可信来源，以及 referrer 与 ancestor origin 冲突都会失败关闭。绝不使用通配 target origin。

## 考虑过的替代方案

**只刷新 iframe。** 拒绝。外层六阶段界面仍会陈旧，并可能停在另一个镜头。

**只信任 `document.referrer`。** 拒绝。外层 referrer policy 可能合法清空它。浏览器只读 ancestor origin 可作后备来源，但两个来源同时存在且不一致时会拒绝通道。

**POST 成功后立即发送通知。** 拒绝。响应未知时必须先恢复原回执；无论响应明确还是恢复成功，都还须完成权威回读与当前 context 绑定，才能确认实际保存对象。

## 结果

打开准确本地青木入口会直接进入已绑定的导演工作区。人工保存和采纳保存都能让外层刷新定位，而不新建第二份业务记录；重复投递和重启恢复也保持安全。消息仅用于通知：不授予 Provider、费用、批准、选择、Ready、发布或人工签收权力。正式外层接收器仍由独立 Writer 切片拥有；Harness 浏览器测试使用遵循同一合同的接收器，端到端证明这条边界。
