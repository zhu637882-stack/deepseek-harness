# Agent Note：原生工作台中的完整导演设计

Status: implemented

[English](2026-09-11-qingmu-complete-director-plan.md) | 中文

## 问题

修改机位标签或视频草稿不足以保存完整导演设计。表演、声音、连续性及新增创作字段需要进入同一个持久化规划操作，并保留正式台词身份。

## 决策

原生导演工具读取完整规划响应，通过已有 Writer 场景规划处理器修改创作字段。读取回执绑定当前来源；保存结果不明时，相同请求先恢复原操作，再决定是否写入。验证成功的保存推进当前原生会话上下文，不授予生成或素材采用权限。结构性规划修改保留创作字段及台词表演细节。

引用草稿保存校验本地请求和当前创作来源，不调用供应商预览。绑定来源的 Writer 保存先于临时素材准备，因此供应商链接不可用时，新建本地草稿仍可保存。原生预设明确此顺序；实际预览、核价及生成仍检查素材就绪。组合回归覆盖预览被拒后成功保存和回读，并验证额外模型控制字段在写入前被拒。

完整规划数据保留在已有会话回执事件中，模型接收当前镜头的全部设计及绑定上下文，不重复发送整集规划副本。这使普通多镜头剧集的工具结果无需转存，同时保留来源校验。只有匹配且成功的视图写入日志后，回执才可使用；会话恢复保留配对关系。随包预设回归包含真实转存策略及超过内联容量的剧集。

场景规划与 Writer 使用相同 RFC 8785 规则序列化小数时间和尺度，保存与恢复保留这些数值并使用一致的请求摘要；无关旧回执继续使用原有整数编码。无效数值在传输前明确报错。跨语言摘要样例及原生预设覆盖亚秒级动作节拍。

## 考虑过的替代方案

**另建设计存储**会分裂项目真源。**只改提示词**不会更新正式导演方案。**固定创作字段名单**会丢失后续专项设计。持久化与并发控制由已有规划操作承担。

## 影响

真实原生组合通过命令适配器验证完整方案保存、来源变化、结果不明恢复与上下文续接。Writer 需要配套完整方案 API 改动。引用草稿读取现在单独返回当前剧本、导演与风格来源。导演将它们协调成一份最终生成稿并绑定来源摘要；Writer 编译器只解析素材编号，不再追加隐藏创作指令。旧稿仍可预览和保存，核价及提交前拒绝过时创作来源。工作台展示当前设计并支持作者明确完成协调。摘要证明版本新鲜度，不证明语义一致或艺术质量；真实模型结果和实例部署仍需验证。

当前完整设计同时提供整集连续性摘要，不重复其他镜头的完整方案。拍摄编辑器对照同一批已保存的起止状态，并通过原有规划事务修改开始与结束。未编辑的结构化字段在冲突恢复时也保留；重新基于当前版本准备时只继承明确编辑过的起止字段。不用自动相等规则否定剧本的时间跳跃、换场或动作省略。设计修改后仍需协调引用草稿。

全片对照使用原生模态对话框，避免在窄镜头侧栏挤放表格；原生焦点管理、当前镜头定位和明确选镜保留编辑器已持久化的本地草稿。分镜台与拍摄引用操作均接入已有导演输入框，引用草稿未保存时先保存再交接。输入框可准备完整协调要求，但不会自动发送；追加来源原文不再授予已协调摘要。
