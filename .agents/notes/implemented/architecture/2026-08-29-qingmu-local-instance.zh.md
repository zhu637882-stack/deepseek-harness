# Agent Note: 青木持久本地实例所有权

Status: implemented

[English](2026-08-29-qingmu-local-instance.md) | 中文

## 问题

临时 API fixture（测试前置数据）不是用户持久安装。继承的数据库默认值与陈旧进程标识可能指向无关服务，而静态 Host 令牌的过期与已存 Draft 相互独立。

## 决策

[启动器](../../../../scripts/qingmu-local.py) 独占创建私有根目录，将正常 Studio API 与构建后的 CLI（命令行界面）profile 绑定到它。管理进程持有生命周期 flock 与存活子进程句柄；私有 Unix socket 对控制请求鉴权。状态分别核对 API 身份/数据绑定、Host 监听及登录。持久化 PID 不是信号目标。

显式登录使用权威 API，仅重启自有 Host 更新环境令牌；服务端正常有效期仍被校验。登录和启动均不重放命令。冷备份与恢复检查数据库/媒体完整性；恢复只写不存在的目标目录。

## 考虑的替代方案

**常驻测试 fixture。** 不采用，因为测试身份、关闭 lifespan 和重新播种不具备用户部署语义。

**按保存的 PID 或端口停止。** 不采用，因为崩溃后它们可能属于其他进程。

**新建浏览器账号平台。** 延后。专用 OS 用户凭据与显式登录命令覆盖此单用户安装，不另建身份数据库、不改 JWT 校验。

## 影响

实例仅监听 loopback，信任本地 OS 用户；不支持多租户，也不自动收复管理进程被外部强杀后遗留的子进程。登录会短暂中断 Host 连接，未知结果走既有回执恢复。空驾驶舱没有项目创建入口。[指南](../../../../docs/cookbook/qingmu-local.zh.md) 明确这些限制。聚焦所有权测试及实际启动器/浏览器测试覆盖进程清理、过期恢复、持久 Draft/回执读回；合成 Ready 输入仍是验收数据，不是内容批准。
