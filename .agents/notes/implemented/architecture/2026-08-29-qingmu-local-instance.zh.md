# Agent Note: 青木持久本地实例所有权

Status: implemented

[English](2026-08-29-qingmu-local-instance.md) | 中文

## 问题

临时 API fixture（测试前置数据）不是用户持久安装。继承的数据库默认值与陈旧进程标识可能指向无关服务，而静态 Host 令牌的过期与已存 Draft 相互独立。

## 决策

[启动器](../../../../scripts/qingmu-local.py) 独占创建私有根目录，将正常 Studio API、限定范围的工作流 Worker、构建后的 DSh Host/导演 profile 和易梦六阶段前端绑定到它。易梦前端是唯一用户工作区和业务 UI；启动器只增加 loopback 托管、窄 API 反代和 HttpOnly 会话引导，不复制易梦状态，也不另建第二套驾驶舱。项目运行绑定记录一个未激活的精确项目和剧集范围。未激活项目生产时，文本 Worker 只接收其已确认父任务或发布心跳，独立资产 Worker 也只处理已确认的资产父任务。API 使用独立、仅所有者可访问的 socket 与凭据激活该父任务；管理进程在持久化或启动 Worker 前，按实例 SQLite 重验任务能力、范围、状态、清单哈希和调用计划哈希。实例停止时显式激活，会用一个生产模式的完整易梦 Worker 取代这两个受限 Worker；完整 Worker 只处理绑定的项目和剧集，每条 lane 每轮一个任务、一次尝试且只允许一个并发提交。Worker 可轮询已经提交的 Provider 任务，但不重试结果未知的提交。ProviderGate、付费预算、预检确认和用户内容决定仍是权威；历史新鲜度和结果未知记录保持可见，但不冻结新近确认且绑定素材 SHA 的任务。管理进程持有生命周期 flock 与存活子进程句柄；私有 Unix socket 对控制请求鉴权。状态分别核对 API 身份/数据绑定、Worker 存活、DSh Host 监听/页面、前端监听/页面及登录。持久化 PID 不是信号目标。

显式崩溃恢复命令是管理进程被外部中断后将 `dirty` 标记恢复为 `clean` 的唯一入口。当前管理进程在每次替换自有子进程后都会重写带代际号、仅所有者可读的进程账本，包括登录时重启 Host/前端，因此恢复不依赖较旧的状态快照。恢复要求精确实例身份、空闲的生命周期 flock、所有已记录的管理进程与子进程 PID 均不存在、所有已记录的 loopback 端口均未监听、陈旧控制 socket 不可连接、数据库及 sidecar 无打开句柄、WAL 不存在或长度为零，并通过 immutable 完整性检查。它不发送信号、不调用 Provider。在替换运行真相或删除陈旧 socket 前，它先持久记录可重入的恢复意图及原始 PID/端口事实；即使恢复途中再次中断，也能重新核验并续接，不会丢失唯一证据。若生命周期提交成功而意图清理再次中断，启动和备份仍会被阻止，直至同一恢复命令核对审计和停止态真相后完成清理。恢复成功会记录审计回执和已停止运行真相，启动仍是另一个显式动作。

显式登录使用权威 API，仅重启自有 Host 与前端以更新其私密会话环境；服务端正常有效期仍被校验。登录和启动均不重放命令。冷备份与恢复检查数据库/媒体完整性；恢复只写不存在的目标目录。

## 考虑的替代方案

**常驻测试 fixture。** 不采用，因为测试身份、关闭 lifespan 和重新播种不具备用户部署语义。

**按保存的 PID 或端口停止或接管。** 不采用，因为崩溃后它们可能属于其他进程。崩溃恢复遇到任何仍存活的 PID 或监听者都会停止，不会把它们当作所有权证据。

**新建浏览器账号平台。** 延后。专用 OS 用户凭据与显式登录命令覆盖此单用户安装，不另建身份数据库、不改 JWT 校验。

## 影响

实例仅监听 loopback，信任本地 OS 用户；不支持多租户，不向未知进程发送信号，也不会自动恢复无法判定的崩溃。登录会短暂中断 Host 与前端连接，未知结果走既有回执恢复。这个已激活的单一 Worker 可以继续推进已绑定工作流，不创建第二套 Provider 账本，无关项目和剧集仍不具备执行资格。唯一 URL 直接进入真实易梦项目工作区，DSh 导演面板属于同一界面。[指南](../../../../docs/cookbook/qingmu-local.zh.md) 明确这些限制。聚焦所有权测试及实际启动器/浏览器测试覆盖进程清理、崩溃拒绝与恢复、重启持久性、会话引导、限定范围的激活和真实项目状态；合成输入仍是验收数据，不是内容批准。
