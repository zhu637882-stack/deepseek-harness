# Agent Note: 剧本确认前读取产品

Status: implemented

[English](2026-09-15-qingmu-prescript-product-read.md) | 中文

## Problem

新项目的原生编剧调用 `qingmu_read_asset_design` 查看上传的产品参考。Writer 将保存设计的前提也用于读取，导致没有剧本时返回 `asset_design_script_required`。

剧本确认后，素材提示词只收到正文和视觉设定，原始资料里正文代码块以外的人物外形、声线与房间描述没有传入，容易让导演重新猜测。

## Decision

读取沿用规划服务的归属校验，但不要求已有剧本。适配器将缺失的 `script` 和 `scriptSha256` 表示为 null，同时返回创作设定和产品参考。已有剧本的来源校验与保存设计的前提仍由 Writer 执行。

创作设定包含经过哈希核对的原始 `initialBrief`，现有素材提示词将其作为补充来源。当前正式剧本、已存设计及明确修改要求优先于旧稿和旧阶段指令；原始资料不直接拼入图片提示词，也不授予执行权限。

## Alternatives considered

**先创建占位剧本。** 未采用，因为读取上传素材不应创建正式剧本，也不应暗示编剧阶段完成。

## Consequences

编剧可以查看本项目的产品输入。客户端只读发现阶段须兼容没有剧本的状态；保存设计及生成仍满足原有前提。Writer 回归测试覆盖新建产品项目、跨用户拒绝，以及读取和拒绝保存后的存储不变；适配器测试覆盖 GET 返回的空剧本字段与产品参考。

设计上下文增加原始资料的相应长度。Writer 测试核对原始资料完整保留；界面测试将正文外的人物和空间细节传入实际创作请求。视觉执行效果仍需检查生成媒体。

实际审图又发现状态歧义：只表示容纳能力的口袋被画入手机，场景挂架被画入多支可移动毛笔。共用素材创作指引区分承载结构与内容，明确身份参考图中的空容器，保留导演有意设计的携带状态例外，并要求复用前交叉核图。现有创作请求快照覆盖指引传达；修订图片仍需实际审看。

单据图片还把版式说明及未确定的落款解释画成了可见文字。共用创作指引改为逐项给出带引号的准确可见字串，分离版式说明，未定文字留白。

后续图像编辑在描述已改正的情况下仍复制源图的多余内容。共用创作提示按实际像素选择参考：保留可靠身份来源，针对缺陷优先选干净替代图，或说明依据后脱离污染源重建。引用用途正向说明保留内容，不复述错误文字和返修历史；沿用同一坏图堆叠否定词不作为返修方法。
